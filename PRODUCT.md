# Product

## Register

product

## Users

People who want a browser to do things for them without leaving what they're doing: developers and
founders testing their own web apps on localhost, operators clicking through admin dashboards
(bills, approvals, purchase requests), and anyone who'd rather type "create 3 bills with dummy data"
than do it by hand. They summon the bar with a global shortcut while working in another app, type a
sentence, and glance back to see what happened. Sessions are short and frequent; the bar is on screen
for seconds, sometimes minutes during a multi-step goal.

## Product Purpose

Gofer turns plain-English commands into actions in a real browser: single clicks, chains,
multi-step goals, questions about the page, form filling and follow-ups, in the browser the user already
uses (Dia, Arc, Chrome) or a built-in one. Success is the user trusting it enough to let it click in
their accounts: they always know what it understood, what it is doing right now, what it did, and they
can stop it before anything irreversible.

## Brand Personality

Calm, precise, trustworthy. It behaves like a careful assistant, not a flashy demo: quiet chrome, exact
language, results first. The feel is a native macOS command palette in the lineage of Raycast and
Spotlight: instant, keyboard-first, the result is the hero, the UI recedes.

## Anti-references

- Generic AI-tool chrome: purple/blue gradients, glowing accents, glass cards for decoration, emoji icons.
- Translucent windows that pick up the wallpaper and turn every colour muddy (the pink-tinted bar).
- Cramped, truncated layouts where chips and long titles crowd out the sentence the user typed.
- Default-blue-everything: accent colour used as decoration instead of meaning.
- Chatbot transcripts: speech bubbles, avatars, "As an AI…" tone.
- Busy dashboards inside a palette: too many tabs, counters and controls competing with the input.

## Design Principles

1. **The command is the hero.** The input and the latest result dominate; everything else recedes until needed.
2. **Show understanding before action.** Make visible what was understood (the rewritten goal, the target
   tab, the step about to run), so trust is earned, not assumed.
3. **Interrupt only for consequence.** Ask (Allow / Stop) only where an action is risky; otherwise stay quiet and fast.
4. **Native, not novel.** Follow macOS conventions (materials, keyboard behaviour, focus, Reduce Motion)
   so it feels like part of the system.
5. **Every pixel is state.** Colour, motion and icons always mean something: status, site identity,
   progress. Never decoration.

## Accessibility & Inclusion

- Keyboard-first: every action reachable without a mouse, with visible focus states and predictable Esc behaviour.
- Respect macOS Reduce Motion: animations become instant or simple fades.
- High contrast: WCAG AA for all text, including secondary text; no meaning carried by colour alone
  (status always has an icon or word too).
